<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Supabase Realtime | Subscription filtered by client_id; RLS on notifications table provides defense-in-depth |
| browser → PATCH /api/dashboard/notifications | ids array from client; server scopes update to client_id from auth.uid() |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06-01 | Information Disclosure | Realtime subscription | mitigate | Filter: `client_id=eq.${clientId}` on channel; RLS policy "notifs_own" enforces server-side; anon key cannot bypass RLS |
| T-04-06-02 | IDOR | PATCH ids array | mitigate | .eq('client_id', client.id) on all PATCH UPDATE queries; cannot mark another client's notifications as read |
| T-04-06-03 | Spoofing | GET/PATCH notifications | mitigate | Both handlers require valid session; client_id from auth.uid() only |
| T-04-06-04 | Information Disclosure | clientId prop in NotificationFeed | accept | clientId is exposed to the client component (needed for Realtime filter); the RLS policy enforces server-side isolation regardless of the filter value |
</threat_model>
