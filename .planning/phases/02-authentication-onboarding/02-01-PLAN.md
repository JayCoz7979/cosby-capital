# Plan 02-01: Supabase Auth Setup + Auth Pages

## Objective

Configure Supabase Auth for Cosby Capital and build all four authentication pages with production-grade security: login with rate-limiting, signup with Cloudflare Turnstile bot protection and disposable email blocklist, forgot-password with constant-time response (prevents email enumeration), and verify-email confirmation handler. Also includes TOTP 2FA setup page and reusable UI components required by auth flows.

## Context

- Working directory: `C:\projects\cosby-capital`
- Phase 1 complete: shared utilities exist at `src/lib/` (logger, sanitize, auth, validate, api-error, supabase)
- middleware.ts already protects `/dashboard/*` routes and generates CSP nonces
- supabase/config.toml already created with: JWT expiry 3600s, min password 12, refresh token rotation on, anonymous signins off
- Tailwind config: navy `#0A1628`, gold `#C9A84C`, Playfair Display + DM Sans fonts
- Security mandate: `CosbyCapital_Master_Build_Prompt_v14_FINAL.txt` Section 4 (AUTH & ONBOARDING)
- Tier 1 security: S15-001 (no NODE_ENV bypass), S16-002 (constant-time auth responses), S11-009 (email enumeration prevention)

### Task 3: Create Turnstile server verification utility
Create `src/lib/turnstile.ts`:
```typescript
// Verifies Cloudflare Turnstile token server-side
// Never expose secret key — this runs server-only
export async function verifyTurnstile(token: string, remoteip?: string): Promise<boolean>
```
- POST to `https://challenges.cloudflare.com/turnstile/v1/siteverify`
- Uses `TURNSTILE_SECRET_KEY` env var
- Returns boolean — caller decides error message
- If TURNSTILE_SECRET_KEY not set, returns true (dev-only bypass — log warning)
- Import guard: add `'server-only'` at top

### Task 4: Create disposable email blocklist utility
Create `src/lib/email-blocklist.ts`:
- Hardcoded list of 50+ common disposable email domains (mailinator, guerrillamail, 10minutemail, tempmail, throwam, fakeinbox, sharklasers, etc.)
- Export `isDisposableEmail(email: string): boolean`
- Export `isBlockedDomain(domain: string): boolean`
- These domains should never be used: mailinator.com, guerrillamail.com, 10minutemail.com, tempmail.com, throwam.com, fakeinbox.com, sharklasers.com, guerrillamailblock.com, grr.la, spam4.me, trashmail.com, yopmail.com, maildrop.cc, dispostable.com, mailnull.com, spamgourmet.com, trashmail.at, discard.email, spamex.com, spamfree24.org

### Task 6: Create login page
Create `src/app/auth/login/page.tsx`:
- Server Component that renders a client LoginForm
- Client `LoginForm` component:
  - Email + password fields (both required)
  - "Remember me" checkbox (extends session — optional UX feature)
  - "Forgot password?" link
  - Submit button with loading state
  - On submit: call `supabase.auth.signInWithPassword()`
  - On success: redirect to `/dashboard` (use Next.js router)
  - On error: generic message "Invalid email or password" — never reveal which field is wrong (S11-009)
  - After 5 failed attempts: show "Too many login attempts. Please wait 15 minutes." (Supabase handles this server-side via auth.rate_limit_config)
  - If user has `totp_enrolled=true`: redirect to `/auth/verify-2fa` after password check
- Show Turnstile widget on the form (NEXT_PUBLIC_TURNSTILE_SITE_KEY)
- Link to signup page

### Task 7: Create signup page
Create `src/app/auth/signup/page.tsx`:
- Client SignupForm component with:
  - Business email field (required)
  - Password field with strength indicator (min 12 chars, show requirements)
  - Confirm password field
  - Terms of Service checkbox (required — link to /terms)
  - Turnstile widget (NEXT_PUBLIC_TURNSTILE_SITE_KEY)
  - Submit button
- On submit: POST to `/api/auth/signup` server action (not direct Supabase client call)
- Server action (`src/app/api/auth/signup/route.ts`):
  - Validate email format with Zod
  - Check `isDisposableEmail(email)` — if true, return "Please use a business email address"
  - Verify Turnstile token server-side via `verifyTurnstile()`
  - Call `supabase.auth.signUp()` with metadata: `{ signup_ip: req.headers['x-forwarded-for'] }`
  - Return generic success message regardless of whether email already exists (prevents enumeration)
  - Log attempt (sanitized) with `sanitizeForLog()`
- On success: redirect to `/auth/verify-email?email=[encoded]`
- Honeypot field (hidden input, name="website") — reject if filled

### Task 8: Create forgot-password page
Create `src/app/auth/forgot-password/page.tsx`:
- Single email field + submit
- Server action:
  - Validate email format
  - Call `supabase.auth.resetPasswordForEmail()` (Supabase sends reset link)
  - ALWAYS return success response regardless of whether email exists (constant-time, S11-009)
  - Add artificial 200ms delay on both paths (makes timing attacks harder)
- Show: "If an account exists with that email, you'll receive a reset link within a few minutes."
- Rate limit: max 3 requests per email per hour (store in processed_webhook_events or use Supabase rate limiting)

### Task 9: Create verify-email page
Create `src/app/auth/verify-email/page.tsx`:
- Display: "Check your email — we sent a verification link to [email]"
- Resend button (rate-limited — 1 resend per 60 seconds)
- "Wrong email?" link back to signup
- Auto-check verification status every 5 seconds (polling supabase.auth.getSession)
- On verified: redirect to `/onboarding/step-1`

### Task 10: Create auth callback route
Create `src/app/auth/callback/route.ts`:
- Handle Supabase Auth code exchange (email confirmation, password reset links)
- Extract `code` from URL params
- Call `supabase.auth.exchangeCodeForSession(code)`
- On success: redirect based on type:
  - email confirmation → `/onboarding/step-1`
  - password reset → `/auth/reset-password`
- On error: redirect to `/auth/login?error=invalid_link`
- Never expose error details to client

### Task 11: Create 2FA setup page
Create `src/app/auth/setup-2fa/page.tsx`:
- Protected route (requires auth)
- Show QR code for TOTP enrollment (use Supabase `mfa.enroll()`)
- Show secret key for manual entry (fallback)
- Verification step: enter 6-digit code to confirm enrollment
- On verified: mark session with 2FA complete
- Show backup codes (downloadable as text file)
- "Skip for now" button (only for non-admin accounts)
