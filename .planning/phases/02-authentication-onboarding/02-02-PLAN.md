# Plan 02-02: Device Fingerprint + Trusted Devices + OTP Flow

## Objective

When a user logs in from an unrecognized device, trigger step-up authentication via a 6-digit OTP sent to their email. Once verified, add the device to `trusted_devices` so future logins from that device skip OTP. Implements TIER 1 security item from the build spec (device fingerprint login protection).

## Tasks

### Task 1: Create OTP utility
Create `src/lib/otp.ts`:
```typescript
// Generate a cryptographically secure 6-digit OTP
export function generateOtp(): string
// Constant-time comparison (prevents timing attacks)
export function verifyOtp(provided: string, stored: string): boolean
// Hash OTP before storage (SHA-256 via crypto.subtle or Node crypto)
export async function hashOtp(otp: string): Promise<string>
```
- Use `crypto.randomInt(100000, 999999)` for generation (cryptographically secure)
- `verifyOtp` must be constant-time: use `crypto.timingSafeEqual` after SHA-256 hash of both
- OTPs stored as SHA-256 hash in `trusted_devices` or a separate `device_otps` temp table
- OTPs expire after 10 minutes
- OTPs are single-use (mark `used=true` after first successful use — replay prevention)

### Task 2: Create device fingerprint client utility
Create `src/lib/device-fingerprint.ts`:
- Client-side (use `'use client'` directive or export as function for client components)
- Generate a stable fingerprint from: `navigator.userAgent`, `navigator.language`, `screen.width`, `screen.height`, `screen.colorDepth`, `Intl.DateTimeFormat().resolvedOptions().timeZone`, canvas fingerprint (basic, non-intrusive)
- SHA-256 hash the concatenated string to produce a 64-char hex fingerprint
- Export: `generateFingerprint(): Promise<string>`
- This fingerprint is sent to the server for device trust lookup — never used as an auth token

### Task 3: Create device_otps table migration
Create `supabase/migrations/20240101000006_device_otps.sql`:
```sql
CREATE TABLE device_otps (
  id uuid primary key default uuid_generate_v4(),
  created_at timestamptz default now(),
  user_id uuid references auth.users(id) on delete cascade,
  fingerprint_hash text not null,
  otp_hash text not null,
  expires_at timestamptz not null default (now() + interval '10 minutes'),
  used boolean default false,
  attempt_count integer default 0
);
ALTER TABLE device_otps ENABLE ROW LEVEL SECURITY;
-- Only service_role can read/write (edge functions use service_role)
CREATE POLICY "service_role_only" ON device_otps FOR ALL
  USING (auth.role() = 'service_role');
-- Auto-cleanup expired OTPs
CREATE INDEX idx_device_otps_expires ON device_otps(expires_at);
```
Note: `trusted_devices` table was created in migration 003. This migration only adds the OTP temp table.

### Task 4: Create check-device route
Create `src/app/api/auth/check-device/route.ts` (POST):
- Input (validated with Zod):
  ```typescript
  { fingerprint_hash: string } // max 64 chars
  ```
- Auth: requires valid session (from middleware)
- Query `trusted_devices` for `user_id = auth.uid() AND fingerprint_hash = $1 AND is_revoked = false AND (expires_at IS NULL OR expires_at > now())`
- Update `last_seen_at = now()` on match
- Response:
  ```typescript
  { trusted: boolean, device_name?: string }
  ```
- If not trusted: client should trigger OTP flow
- Log check result with sanitizeForLog() (no fingerprint in logs — hash only first 8 chars)

### Task 5: Create send-device-otp route
Create `src/app/api/auth/send-device-otp/route.ts` (POST):
- Auth: requires valid session
- Input: `{ fingerprint_hash: string }`
- Rate limit: max 3 OTP sends per user per 15 minutes (check device_otps count)
- Generate OTP via `generateOtp()`
- Hash OTP via `hashOtp()`
- Insert to `device_otps`: `{ user_id, fingerprint_hash, otp_hash, expires_at: now()+10min }`
- Send email via Resend:
  - To: user's email
  - Subject: "Cosby Capital — New Device Login Verification"
  - Body: "Your verification code is: **[OTP]**. This code expires in 10 minutes. If you did not attempt to log in, contact security@cosbycapital.com immediately."
  - Footer: "Powered by Cosby AI Solutions | cosbyaisolutions.com"
- Always return `{ sent: true }` regardless of email success (prevents enumeration)
- Log with sanitizeForLog() — never log OTP itself

### Task 6: Create verify-device-otp route
Create `src/app/api/auth/verify-device-otp/route.ts` (POST):
- Auth: requires valid session
- Input (Zod): `{ otp: string (max 6 chars), fingerprint_hash: string, device_name?: string }`
- Fetch latest unused, non-expired OTP for `user_id + fingerprint_hash`
- If no OTP found: return 400 `{ error: "Code expired or not found" }`
- Check attempt count: if `attempt_count >= 3`, increment and return 429 `{ error: "Too many attempts. Request a new code." }` — also mark existing OTP as used to prevent brute force
- Increment `attempt_count` BEFORE verification (prevents race condition exploitation)
- Verify: `verifyOtp(provided_otp, stored_otp_hash)` — constant-time
- On failure: return 400 `{ error: "Invalid code" }` — always same latency
- On success:
  - Mark OTP as `used=true`
  - Insert to `trusted_devices`: `{ user_id, fingerprint_hash, device_name: device_name || 'Unknown Device', trusted_at: now(), expires_at: now()+90days }`
  - Return `{ trusted: true }`
- Minimum response time: 50ms (match verifyOwnership pattern from lib/auth.ts, S16-004)

### Task 7: Create DeviceTrustModal component
Create `src/components/auth/DeviceTrustModal.tsx` (client component):
- Props: `{ isOpen: boolean, onVerified: () => void, fingerprintHash: string }`
- Modal dialog (use Radix UI Dialog or custom accessible modal)
- Shows: "New Device Detected — Enter the verification code sent to [email]"
- 6-digit OTP input (auto-focus, numeric keyboard on mobile)
- "Verify" button + loading state

- Error state for wrong code
- On verify success: call `onVerified()` callback → close modal → proceed to dashboard
- Calls: `POST /api/auth/check-device` → `POST /api/auth/send-device-otp` → `POST /api/auth/verify-device-otp`

### Task 8: Integrate device check into login flow

## Must-Haves

- [ ] OTP stored as SHA-256 hash — never plaintext (replay prevention)
- [ ] `verifyOtp()` uses `crypto.timingSafeEqual` — constant-time comparison
- [ ] OTPs expire after 10 minutes (enforced server-side, not just display)
- [ ] After 3 failed OTP attempts: lock out further attempts on that OTP record (mark used)
- [ ] `device_otps` table has RLS — only service_role can read/write
- [ ] OTP value never appears in any log (only `otp_hash` if needed for debugging)
- [ ] `trusted_devices` records expire after 90 days
- [ ] Verify-device-otp response time is constant (minimum 50ms, matching S16-004)
- [ ] No NODE_ENV bypass for device trust check
