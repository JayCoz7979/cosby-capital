# Plan 02-03: 6-Step Onboarding Wizard

## Objective

Build the complete client onboarding flow from business basics through subscription selection. Each step saves progress to `onboarding_sessions`. Step 4 performs KYB + OFAC + beneficial ownership screening. Step 5 triggers signature (wired to Plan 02-04 components). Step 6 shows subscription tiers (wired to Plan 02-05 Stripe checkout). All steps enforce authentication and guard against re-entry on completion.

### Task 1: Create DB migration for beneficial_owners + ofac_screenings
Create `supabase/migrations/20240101000007_onboarding_tables.sql`:

```sql
-- Beneficial owners (Corporate Transparency Act)
CREATE TABLE beneficial_owners (
  id uuid primary key default uuid_generate_v4(),
  created_at timestamptz default now(),
  client_id uuid references clients(id) on delete cascade not null,
  full_name text not null,
  date_of_birth date,
  ssn_last4 text,
  address text,
  ownership_percentage numeric check (ownership_percentage >= 0 and ownership_percentage <= 100),
  ofac_screened boolean default false,
  ofac_screened_at timestamptz,
  ofac_result text default 'pending' check (ofac_result in ('pending','clear','flagged','blocked')),
  ofac_match_score numeric,
  ofac_notes text
);
ALTER TABLE beneficial_owners ENABLE ROW LEVEL SECURITY;
CREATE POLICY "bo_own" ON beneficial_owners FOR ALL
  USING (client_id IN (SELECT id FROM clients WHERE user_id = auth.uid()));

-- OFAC screening log
CREATE TABLE ofac_screenings (
  id uuid primary key default uuid_generate_v4(),
  created_at timestamptz default now(),
  client_id uuid references clients(id) not null,
  screening_type text not null check (screening_type in ('business','individual')),
  entity_name text not null,
  entity_dob date,
  result text not null check (result in ('clear','flagged','blocked')),
  match_score numeric,
  raw_response jsonb,
  reviewed_by text,
  reviewed_at timestamptz,
  disposition text
);
ALTER TABLE ofac_screenings ENABLE ROW LEVEL SECURITY;
-- Clients can read own screenings; admins can see all
CREATE POLICY "ofac_own_read" ON ofac_screenings FOR SELECT
  USING (client_id IN (SELECT id FROM clients WHERE user_id = auth.uid()));
CREATE POLICY "ofac_service_write" ON ofac_screenings FOR INSERT
  WITH CHECK (auth.role() = 'service_role');

-- Add OFAC columns to clients table
ALTER TABLE clients ADD COLUMN IF NOT EXISTS ofac_status text default 'pending'
  CHECK (ofac_status in ('pending','clear','flagged','blocked'));
ALTER TABLE clients ADD COLUMN IF NOT EXISTS ofac_screened_at timestamptz;
ALTER TABLE clients ADD COLUMN IF NOT EXISTS beneficial_ownership_collected boolean default false;
```

### Task 2: Create verify-kyb edge function
Create `supabase/functions/verify-kyb/index.ts`:
- Accepts: `{ ein: string, business_name: string, state: string, client_id: string }`
- Auth: service_role header check (INTERNAL_SERVICE_SECRET)
- EIN format validation: `^\d{2}-\d{7}$`
- Cross-reference strategy (graceful degradation):
  1. If `KYB_VENDOR` env = 'middesk': call Middesk API
  2. If `KYB_VENDOR` env = 'persona': call Persona API
  3. Default: basic format validation + log for manual review (acceptable at launch)
- On verified: `INSERT INTO kyb_verifications`, update `clients.kyb_status = 'verified'`
- On failure: update `clients.kyb_status = 'failed'`, send Telegram alert
- Returns: `{ verified: boolean, status: string, notes?: string }`
- All inputs: `sanitizeForPrompt()` before any external API call
- Log result with `sanitizeForLog()` — never log EIN in plaintext

### Task 3: Create screen-ofac edge function
Create `supabase/functions/screen-ofac/index.ts`:
- Accepts: `{ entity_name: string, entity_type: 'business'|'individual', entity_dob?: string, client_id: string }`
- Auth: service_role header check (INTERNAL_SERVICE_SECRET)
- Screening logic:
  1. If `OFAC_VENDOR='middesk'|'persona'|'alloy'`: call vendor API
  2. Default ('direct'): call OFAC SDN API at `https://sanctionssearch.ofac.treas.gov/SdnList.aspx` (search endpoint) or use the downloadable SDN list (cached daily)
  3. Fuzzy match: exact match = block (score 100), score >= 85 = flagged, < 85 = clear
- Insert to `ofac_screenings` table
- Update `clients.ofac_status` based on result
- On 'blocked': `UPDATE clients SET kyb_status='blocked', ofac_status='blocked'` + Telegram alert IMMEDIATELY
- On 'flagged': `UPDATE clients SET ofac_status='flagged'` + Telegram alert within 1 minute
- Returns: `{ result: 'clear'|'flagged'|'blocked', match_score: number, matches: any[] }`
- Inputs: `sanitizeForPrompt()` — personal data (names, DOBs) must not leak into logs
